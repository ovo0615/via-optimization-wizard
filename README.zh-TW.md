## 這個專案要解決什麼

Ansys optiSLang 的多目標最佳化功能強大，但第一次接觸的工程師往往在
「參數怎麼註冊、流程怎麼接、結果怎麼看」就迷路了。這個專案把一個真實的
訊號完整性題目——**PCB 差分 via 的幾何最佳化**——包成四步精靈：

1. **選範例與疊構**：內建 12 層板差分 via（含 backdrill），或讀取自己板子的疊構
2. **定義設計空間**：四個幾何變數（antipad、pitch、GND via 距離、殘樁長度）
   拉範圍即可，旁邊即時顯示 via 佈局與零求解的解析指標
3. **目標與約束**：反射（TDR |Γ| 峰值）vs 佈線 keep-out 面積的雙目標取捨，
   殘樁共振頻率當約束——太長的 stub 讓陷波掉進工作頻寬，直接淘汰
4. **執行**：optiSLang 三段式流程背景執行，網頁看進度，跑完一鍵開
   optiSLang 原生後處理

## 設計空間的兩端都由實體決定，不是拍腦袋

殘樁長度的範圍是這樣來的：

```
stub_mm   0.15  ~  0.8933
            ↑         ↑
    backdrill 公差   共振下限 40 GHz
```

**上界是算出來的，不是猜的。** 共振 = c / (4 · stub · √Dk) 對 stub 嚴格
遞減，所以「共振 ≥ 40 GHz」與「stub ≤ 0.8933 mm」**完全等價**。把約束寫
成設計空間的邊界，好過讓最佳化器跑到不可行區再用懲罰值把它拉回來——
後者會讓代理模型去學一道人造的懸崖（實測讓 CoP 從 97.9% 掉到 89.4%），
還白白花掉 11% 的取樣預算。

**下界是製程能力。** 0.05 mm 的殘樁只有 50 µm，低於 backdrill 的典型公差
（±50～100 µm）——最佳化器不該推薦一個做不出來的設計。這個數字要照你的
供應商實際能力調整，它不是物理常數。

附帶收穫：0.05 mm 附近也是 HFSS 的不穩定區。同一組幾何，殘樁 0.05 mm 時
4 次求解有 3 次卡在頻率掃描階段（停滯 88 / 33 / 15 分鐘，CPU 不動），
改成 0.15 mm 就一次解完（12.7 分鐘）。**最佳化器最愛去的角落，正好是
求解器最不可靠的地方**——自動化流程沒有停滯偵測的話，會安靜地卡在
最重要的那一個點上。

**這個下界要付多少代價，我們量了，而且把它跟雜訊分開。** 新邊界重跑
72 點之後，新的 Pareto 前緣在同面積下比舊的差 0.021～0.033，很容易就
順口說成「製程限制的代價」。但拆開來不是：

| 來源 | 同面積下的 \|Γ\| 增量 |
| --- | --- |
| 製程下界本身（同一份舊資料、只把下界 0.05 改成 0.15） | +0.013 ～ +0.017 |
| 兩個研究的模型歧異（kriging vs quadratic、不同樣本） | +0.004 ～ +0.021 |

**兩者量級相同。** 把整個差距講成製程代價會誇大一倍——而這種誇大在
簡報上完全看不出來，因為兩條前緣畫在一起就是「新的比較差」。要分開只
有一個辦法：**固定模型改邊界，再固定邊界換模型**，兩次各自量一次。

還有一件事值得說：兩次最佳化的前緣**整條都貼在 stub 下界上**
（舊界 0.050～0.055、新界 0.150～0.159）。也就是最佳化器對殘樁的答案
永遠是「你的製程能鑽多深就鑽多深」，真正的取捨發生在 antipad、pitch 與
GND 距離對面積的權衡上。**下界訂在哪，答案就落在哪**——所以這個數字要
照供應商的實際能力填，它不是物理常數。

## 為什麼是 via、為什麼是 TDR

via 是 SI 工程師每天面對的結構，antipad、回流路徑、backdrill 殘樁這些
教科書問題全部交會在這裡。而 TDR 阻抗剖面是最能「對症下藥」的觀測方式：
凹下去是電容性（antipad 太小、pad 太大），凸起來是電感性（GND via 太遠、
pitch 太大）——工程師看一眼就知道往哪個方向調。

兩個目標真的互相打架：antipad 開大、GND via 拉遠對電性好，但佔掉佈線
面積。這正是 Pareto 前緣存在的理由——optiSLang 把整條取捨曲線攤出來讓
你選，而不是只給一個「最佳解」。

## 技術架構

```
設計變數 ──> 模型描述(JSON) ──> PyEDB 建模 ──> HFSS 3D Layout 求解
                                                      │
optiSLang 三段式流程                                Touchstone
  敏感度分析（ALHS，真解，平行派發）                    │
  ↓                                            scikit-rf IFFT
  MOP 代理模型                                        │
  ↓                                            TDR 阻抗剖面
  多目標最佳化（EA，在 MOP 上，秒級）  <── |Γ| 峰值抽取 ┘
```

- **每個設計點完整重建模型**：幾何由參數化 JSON 描述重新產生，
  不依賴 AEDT 變數——這讓求解器成為可換的介面（HFSS／預跑查表／
  未來的 SimAI）
- **真解只發生在敏感度階段**：EA 的數百次評估全部打在 MOP 代理模型上，
  HFSS 不在場也能重跑最佳化、改權重
- **三個響應的取得成本刻意差三個數量級**：keep-out 面積（幾何公式）、
  殘樁共振（四分之一波長解析式）、反射峰值（HFSS 求解）——違反約束的
  設計在求解之前就被跳過，一秒都不浪費

## 實測數字（14 核筆電、4 核／點、2 並行）

| 項目 | 數字 |
| --- | --- |
| 建模（JSON → .aedb，12 層板） | 35 秒 |
| HFSS 單點求解（40 GHz 掃頻） | 4～5 分鐘（暖機後） |
| **第一個設計點**（含 AEDT 冷啟動） | **30 分鐘以上** |
| 120 點敏感度研究（2 並行） | 7.1 小時（每個真解點 4.1 分） |
| EA 最佳化 90～240 評估（MOP 上） | 秒級 |
| 載入預跑備援 | 0.45 秒 |
| 代理模型重新擬合＋NSGA-II（純 Python） | 約 25 秒 |

**第一個點要 30 分鐘以上**是示範時最容易踩的地雷：AEDT 冷啟動與 .NET
組件載入都算在第一個設計點頭上。要現場真解就先解一個點把它暖起來。

並行數不要超過 2：3 並行時 HFSS 的 MPI 管理員 `hydra_pmi_proxy.exe`
會連續崩潰（0xC0000005，實測 4 次）。

掃頻上限 40 GHz 是用單調性實測定出來的：四個已知好壞順序的設計，
20 GHz 下 |Γ| 排序整個亂掉（TDR 解析度比整根 via 長），40 GHz 與
60 GHz 排序完全一致——最佳化需要的是排序正確，40 GHz 就夠。

### 這裡的數字改過，原因值得講

先前這一節寫的是「凹陷差 1.4%、回穩差 12.7 Ω 尚未收斂」。查下去發現
**那個漂亮的 1.4% 是兩個錯誤互相抵消的結果**：

HFSS 匯出的 Touchstone 在極低頻（實測約 1 MHz 以下）填的是外推值，不是
解出來的——五個設計在 0.1 MHz 的差分阻抗分別是 63.7 / 75.0 / 84.1 /
88.6 Ω，每個檔案錯得不一樣，而真值是 84～86 Ω。階躍響應的終值就是
ρ(DC)，所以那段假資料把整條 TDR 曲線的基線往下拉，實測 107 個設計
系統性低 **19.5 ± 7.1 Ω**。基線被拉低，凹陷的絕對值也跟著被拉低，於是
剛好和 AEDT 的凹陷對上了。

修法是丟掉 10 MHz 以下的資料，讓外推從平坦區開始（差分 via 電氣尺寸極小，
阻抗從 DC 到數 GHz 是平的，那個頻段沒有物理資訊）。修完：

- 回穩值與頻域的差距 19.5 ± 7.1 Ω → **0.5 ± 0.1 Ω**（107 個設計，全距 0.1～0.8）
- |Γ| 中位數變動 −2.9%，名次 Spearman **0.9982**（最大移動 8 位）
- 但凹陷深度的一致性從 1.4% 變成 15.3%——**基線對了，凹陷還沒對**

凹陷仍差 15.3% 這件事照實列在這裡。本工具的曲線明顯較平滑（它有依解析度
的平滑處理，AEDT 沒有），這解釋得了方向但解釋不了幅度。要對外引用**絕對**
凹陷深度之前得先收斂它；用於最佳化的排序不受影響（名次相關 0.9982）。

## 我們自己驗證自己的推薦

代理模型算出來的 Pareto 前緣，上面的 |Γ| 是**預測值不是解出來的**。所以
把前緣上 |Γ| 最低的那個設計真的用 HFSS 解一次（4 分鐘）：

| | |
| --- | --- |
| 代理模型預測 | 0.0487 |
| **HFSS 實際** | **0.0790** |

**錯 38%。** 而那個代理模型的 CoP 是 0.9799——看起來非常好。

原因是最佳化器**永遠把設計推到設計空間的角落**（那個設計四個變數有三個
頂在邊界），而角落是外推區。CoP 是在內部樣本上量的，從不檢驗外推行為。
同一份資料上，高斯過程在該點預測 0.0751（誤差 −5%），RBF 預測 0.0487
（誤差 −38%），兩者的 CoP 只差 0.0015——雜訊等級的差距，卻決定了模型
好壞。高斯過程離開資料會回歸平均值；RBF 外推無界，能憑空生出「比看過的
每一個設計都好」的假最佳解。

修法：CoP 差在 0.01 以內視為平手，平手時依外推安全性選模型。誤差從
−38.4% 降到 −14.9%，CoP 只從 0.9799 掉到 0.9792。

**這件事對任何代理模型最佳化都成立，包括 optiSLang 的 MOP。** 所以工具
內建「把推薦的最佳解真的解一次」這一步——4 分鐘換一個可以拿去跟客戶講的
數字，很划算。

### 換到新的設計空間之後：三個點都真的解過

72 點研究重跑之後，前緣上三個位置各解一次 HFSS。實際 \|Γ\| 是量到的物理量；
預測值來自現行程式碼（69 點敏感度資料擬合，這三個點都不在訓練集裡）：

| 驗證點 | 面積 | 預測 \|Γ\| | **實際 \|Γ\|** | 誤差 |
| --- | --- | --- | --- | --- |
| **膝點** | 4.87 mm² | 0.1146 | **0.1237** | −7.3% |
| 端點 A | 14.49 mm² | 0.0933 | **0.0851** | +9.6% |
| 端點 B | 6.75 mm² | 0.0920 | **0.0894** | +2.9% |

三個點的誤差都在 10% 以內。**但這張表不是「該拿哪一點」的依據**——
n = 3 撐不起「誰比較準」的結論。真正的依據在下一節。

### 真正的依據：端點會跳，膝點不會

同一份資料，每補一個真解點就重新擬合一次，看推薦往哪裡跑：

| 訓練點數 | 選中的模型 | **端點**面積 | **膝點**面積 | 膝點 GND 距離 |
| --- | --- | --- | --- | --- |
| 69 | kriging（3 變數） | 6.80 mm² | 5.42 mm² | 0.600 |
| 70 | kriging（4 變數） | **16.55 mm²** | 6.06 mm² | 0.602 |
| 71 | kriging（3 變數） | 6.62 mm² | 5.60 mm² | 0.600 |

**端點擺盪 2.4 倍，膝點只擺盪 12%，而膝點的 GND 距離幾乎釘死在邊界上。**

原因是 **GND 距離對反射沒有影響**——就是 CoP 矩陣裡那個灰格。沒有影響
就沒有訊號，模型在那個方向上學到的只有雜訊：

```
69 點：相關係數 −0.0142  →  gnd 0.6 拉到 1.4，預測 |Γ| 變 −0.00513  →  端點跑到 gnd = 1.4
70 點：相關係數 +0.0079  →  gnd 0.6 拉到 1.4，預測 |Γ| 變  0.00000  →  端點跑到 gnd = 0.6
```

一個 **0.005** 的預測變化——比模型自身的驗證誤差還小——就足以讓端點在
設計空間的兩端之間跳。而 GND 距離對**面積**的貢獻是 88.6%，所以那個雜訊
一翻號，推薦面積就跟著翻倍。

膝點不受影響，是因為它由前緣的**形狀**決定，不是由某一端的極值決定。
雜訊改變不了「取捨在哪裡開始變得不划算」。

實務上的三個結論：

1. **拿膝點給客戶，不要拿端點。** 依據是穩定性（12% vs 240%），不是準確度
   ——三個真解點的誤差都在 10% 以內，n = 3 撐不起「誰比較準」的宣稱。
2. **CoP 矩陣的灰格要當成結論看**，不是「沒資料」。灰格代表那個參數可以
   照其他考量（成本、可製造性、佈線）自由決定——這往往比最佳化結果本身
   更有用。
3. **驗證要跑不只一次。** 補點會移動推薦，跑到不再移動才算收斂。

### 附帶抓到一個選模型的瑕疵

上表「69 點選 3 變數、70 點選 4 變數」這件事本身也值得講。挑代理模型的
規則寫的是「CoP 差在 0.01 以內視為平手，平手時選變數少的」，但實作是把
CoP 除以容忍度**四捨五入成格子**：

```python
bucket = -round(cop / 0.01)     # 0.9616 → 96 格；0.9547 → 95 格
```

兩者只差 0.0070，在容忍度內理應平手，卻落在不同格子——**平手規則從來
沒有生效過**。同一份 69 點資料，修正前選 quadratic／四變數（CoP 0.9616），
修正後選 kriging／三變數（CoP 0.9518）。

修法是不要有格子：先找出全場最高的 CoP，距最高不到容忍度的一律算平手。
**任何「量化成格子再比較」的容忍度判斷都有這個邊界瑕疵**，而它不會拋錯、
不會有警告，只會安靜地選錯。
